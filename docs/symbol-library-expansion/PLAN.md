## Directional-valve configurator (director instruction)

Detents and spool controls go **into the configurator** (`fl.hyd.dcv` / `fl.pneu.dcv`), and are also offered as
standalone, non-connectable operator elements (group "Valve operators") for hand-built valves.
The valve dialog reads `OPERATORS` and `PATTERNS` from `symbols/fluid.py`, so new operators and centre
conditions appear in the dialog without GUI changes. Every existing valve configuration must render exactly as
before (golden-geometry regression test against the unmodified builder).

Planned operators: detent, push-pull knob, pedal (single / double acting), plunger, plunger with stroke limit,
roller, lever with roller, cam (mechanical), push/pull solenoid, proportional solenoid, direct pilot, internal and
external pilot (triangle-in-box), released-pressure pilot (remote exhaust / internal return), pilot differential,
solenoid-operated pilot (internal / external supply), electric motor, reversing motor, other control unit,
coupling, thermal (local / bulb), pressure compensated, servo.
Planned flow patterns: the eight three-position centre conditions of Y32 10.11.3 and the HO spool forms, where not
already present.

## Drawing rules applied to every new symbol

* Native primitives only (line / poly / circle / text; arcs flattened) — no raster, no copied SVG paths.
* Terminals on the 10-unit grid with an outward direction; port types from `PORT_TYPES`
  (hydraulic letters P, T, A, B, X, Y, L; pneumatic numbers 1, 2/4, 3/5, 10/12/14).
* Ids are stable and never reused; names state the operating principle and normal position.
* Convention field: `ISO 1219-1 style`, `ANSI Y32.10 style` (new constant) only for symbols with no ISO
  equivalent drawing, `IEC 60617 style` / `IEEE 315` style per the drawing. No claim of formal compliance.
* Source features are not invented. Where a figure is unclear the row is `decision` or `blocked` with a reason.

## Validation (per batch, automated)

1. every new definition builds and passes `validate_geometry`; 2. ids unique across all built-ins; 3. terminals
on grid, unique names, valid direction and port type, port domain consistent with the category; 4. geometry
finite, non-degenerate, terminals on or outside the drawn extent; 5. renders to SVG and PDF via `export`;
6. placed in a project; 7. a wire drawn to each terminal attaches to that terminal and appears in the netlist;
8. save → reopen keeps symbol, params, terminals and connections; 9. every existing built-in symbol (and every
existing valve configuration) renders identically to main; 10. a guard test fails if production modules other
than the bundled symbol definitions change on this branch. Contact sheets (`tools/symbol_contact_sheet.py`)
are generated for visual comparison against the sources.

## Director decisions (2026-11-01)

* **Q1 — both styles.** Where Y32.10 draws a function that already has an ISO 1219 symbol, an ANSI Y32.10-style
  symbol is added beside it (id suffix `.ansi`, convention "ANSI Y32.10 style"). If, when drawn, the ANSI figure is
  identical to the ISO symbol, the row is marked `equivalent` instead of adding a pixel-identical duplicate.
* **Q2 — minimal valve-dialog change allowed** in this PR: a third operator slot per side, a proportional
  (infinite-positioning) option and a transition-position option. Existing valves are unaffected.
* **Q3 — composite assemblies left out** (steering units, mobile sectional valves, complete FRL, Y32 section 11
  examples): status `excluded`; they are built from the individual symbols inside a component enclosure.
* **Q4 — unlabelled / ambiguous ECL drawings left out**: status `blocked` with the reason, to add once identified.

Scope note: because of Q2, `openschematix/gui/dialogs.py` (ValveDialog only) is the one non-library production
file this PR may change. The changed-files guard test allows exactly that.
